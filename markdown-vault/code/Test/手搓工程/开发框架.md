```markdown
## 面向对象/接口化架构

### 解耦

- 高层模块（业务）不依赖低层模块（硬件），两者都依赖抽象（接口）

### 封装

- 建仓库

	- struct打包（配置+数据+操作），建静态池管理

- 锁大门

	- static锁.c文件（信息隐藏）

- 发工作证（句柄）

	- struct前向声明，函数接口操作（不透明句柄）

- 划仓储区

	- 局部、文件静态、全局受控（编号归类）

### 继承

- “基类”（共性）作为“子类”（特性）结构体

- 特例“组合”协作关系，继承（放首位），组合（放末尾）

### 多态

- 把“行为”装入变量：函数指针，等效“虚函数”

- 依赖注入：初始化虚函数表（vtable），把子类给父类注册函数

- 物以类聚：虚函数表（vtable），引入“操作表（ops）”

- 一对象一导航：vptr（虚表指针）

- 同名函数不同行为：动态多态

### 工程

- “转型”问题

	- 向上转型：把“子类”当“父类”用

	- 向下转型：从“父类”找回“子类”（container_of)

- “铁腕执行”：纯虚函数

	- 初始化置NULL：函数指针设为NULL

	- “弱”默认实现：默认的weak_on函数

	- 编译期阻截：用#error或静态断言

- OOP完整框架

	- 上层业务逻辑（App）和底层硬件（Driver）(平台抽象层)

	- 链接器自动初始化（initcall）：绑定到特殊内存段中
```
