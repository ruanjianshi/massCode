# 中断、并发与实时性

## 1. ISR 红线

ISR 中必须：

- 读取并清除必要的硬件状态。
- 保存最少的时间敏感数据。
- 使用 ISR-safe API 释放信号量、设置标志或写入预分配队列。
- 在可能的情况下立即返回。

ISR 中禁止：

- 动态内存分配和释放。
- 阻塞锁、延时、文件系统、格式化日志。
- 复杂协议解析和长循环。
- 调用未明确声明可在 ISR 中使用的 HAL/RTOS API。
- 直接进入业务状态机或依赖上层事件框架。

## 2. 推荐的中断传递路径

```text
硬件 ISR
  → 清中断 + 发送极简通知
  → 高优先级驱动工作线程
  → 读取硬件/更新驱动状态
  → 任务上下文回调
  → 应用选择 FIFO、LIFO 或 publish
```

驱动只提供事件和数据，不包含上层消息框架头文件。

## 3. 回调契约

每个回调类型必须记录：

- 调用上下文：ISR、工作线程还是调用者线程。
- 是否允许阻塞。
- 是否允许重入驱动。
- 回调期间驱动持有哪些锁。
- 数据所有权及有效时间。
- 注销回调时如何等待在途调用完成。

默认不应持有驱动内部锁调用外部回调，否则容易产生反向调用死锁。

## 4. 并发保护选择

| 场景 | 首选机制 |
| --- | --- |
| 线程与线程共享复杂状态 | 互斥锁，需要时启用优先级继承 |
| ISR 通知单个线程 | 线程标志或二值信号量 |
| ISR/线程传递数据 | 预分配队列或环形缓冲区 |
| 极短寄存器读改写 | 短临界区或原子操作 |
| 单生产者/单消费者字节流 | SPSC 环形缓冲区 |

临界区中不得调用阻塞 API、执行长循环或进行内存分配。

## 5. 阻塞性验证

不能根据 API 名字判断非阻塞。必须追踪到 HAL 或寄存器实现，检查：

- 轮询等待标志位。
- 超时循环和 delay。
- 同步等待 DMA 完成。
- 总线锁和优先级反转。
- 底层弱符号是否被项目覆盖。

事件处理路径上出现的阻塞操作，应移入专用工作线程。

## 6. 时间与超时

- 所有可能等待硬件的操作必须有超时。
- 超时计算使用无符号差值，保证 tick 回绕安全。
- 绝对时限应优先使用单调时钟。
- 优先级、最坏执行时间和队列深度必须通过测量证明。
- 实时任务不依赖无上限的日志、文件系统或动态分配。
