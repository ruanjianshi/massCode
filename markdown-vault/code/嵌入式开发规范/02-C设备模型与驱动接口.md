# C 设备模型与驱动接口

## 1. 基本模型

```c
struct device;

struct device_ops {
	int (*open)(struct device *dev);
	int (*read)(struct device *dev, void *buf, size_t size);
	int (*write)(struct device *dev, const void *buf, size_t size);
	int (*control)(struct device *dev, unsigned int cmd, void *arg);
	int (*close)(struct device *dev);
};

struct device {
	const char *name;
	const struct device_ops *ops;
	const void *config;
	void *data;
	unsigned int flags;
};
```

- `ops` 只读且由同类实例共享。
- `config` 保存出厂参数，初始化后不修改。
- `data` 保存每个实例的运行状态。
- 对象必须通过公共 API 访问，应用不直接解引用私有 `data`。

## 2. 公共 API 的责任

公共包装函数必须统一完成：

1. 检查对象、参数和运行状态。
2. 区分必选与可选 ops。
3. 转换统一错误码。
4. 需要时执行锁、引用计数和跟踪。
5. 再 dispatch 到具体实现。

```c
int device_read(struct device *dev, void *buf, size_t size)
{
	if (dev == NULL || buf == NULL || size == 0U)
		return -EINVAL;
	if (dev->ops == NULL || dev->ops->read == NULL)
		return -ENOSYS;
	return dev->ops->read(dev, buf, size);
}
```

必选 ops 在初始化期检查并拒绝注册；可选 ops 为空时返回确定的 `-ENOSYS` 或提供安全默认行为，不得直接调用空函数指针。

## 3. 嵌入式继承和 container_of

```c
struct gpio_led {
	struct device dev;
	uint32_t pin;
	bool active_low;
};
```

当回调只提供内嵌成员指针时，使用经过审核的 `container_of` 恢复外层对象。

```c
#define container_of(ptr, type, member) \
	((type *)((char *)(ptr) - offsetof(type, member)))
```

约束：

- `ptr` 必须确实指向指定 `member`。
- 对象生命周期必须覆盖回调生命周期。
- 跨编译单元对私有结构使用 `container_of` 应保持在实现文件内。
- 不得用不受控强制转换代替成员偏移计算。

## 4. 设备注册

注册表至少保存名称、类型、对象指针和状态。注册时必须检查：

- 名称不为空且不重复。
- 对象、ops 和必选方法有效。
- 注册容量没有溢出。
- 注册、查找、打开和注销的并发策略明确。
- 注销前已停止中断、DMA、定时器和延迟工作。

## 5. 接口设计规则

- 缓冲区指针始终与长度一起传递。
- 输入指针尽量使用 `const`。
- 返回值明确区分成功数量、无数据、超时与故障。
- 不使用布尔参数同时表达多种策略；复杂配置使用结构或枚举。
- 函数的同步/异步、阻塞/非阻塞和可调用上下文必须写入接口文档。
- 回调中应携带 `context` 或对象指针，不通过全局变量找回状态。
