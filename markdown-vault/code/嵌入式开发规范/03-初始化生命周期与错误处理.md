# 初始化生命周期与错误处理

## 1. 标准状态

```text
UNINITIALIZED → INITIALIZING → READY → ACTIVE
       ↑             ↘ ERROR/DEGRADED ↓
       └────── STOPPING ←──────┘
```

对外 API 必须根据状态决定是否可调用。未初始化对象不得启动 DMA、中断或业务传输。

## 2. 初始化顺序

```text
时钟/内存/日志
  → Board 与引脚复用
  → GPIO/总线/RTOS基础设施
  → 设备驱动
  → 中间件与文件系统
  → 应用任务
```

- 依赖顺序必须由级别、依赖表或显式编排表达。
- 同一级别的模块不应暗中依赖链接顺序。
- 应用启动前必须确认关键设备是否 READY。
- 自动注册需考虑 LTO/GC Sections，链接脚本中需要的段应使用 `KEEP`。

## 3. 资源获取与释放

获取顺序：

```text
分配对象 → 创建锁/信号量 → 配置硬件 → 注册中断 → 启动DMA
```

失败或停止时必须严格逆序释放：

```text
停止DMA → 禁止中断 → 取消延迟工作 → 释放锁 → 释放对象
```

释放前必须防止新请求进入，并等待或取消在途操作。不允许回调在对象销毁后继续访问 `context`。

## 4. 错误处理规则

1. 每个返回值必须处理或显式标注为可忽略。
2. 每一层要么完全处理错误，要么附加上下文后传给上层。
3. 不得将错误统一改为“无数据”或“成功”。
4. 日志应包含设备名、操作、错误码、必要寄存器状态和发生时间。
5. 高频错误需限频，但错误计数器不得丢失。
6. 断言用于程序员违反内部契约；外部输入、硬件故障和通信错误必须运行时处理。

## 5. 关键设备与非关键设备

| 类型 | 例子 | 初始化失败策略 |
| --- | --- | --- |
| 关键 | 安全看门狗、主电源、核心通信 | 禁止进入正常运行，进入安全状态 |
| 可降级 | 次要传感器、扩展存储 | 记录并标记 DEGRADED，其他模块继续 |
| 可选 | 调试端口、附加外设 | 不影响启动，保留诊断信息 |

关键性必须由产品需求定义，不由驱动作者自行猜测。

## 6. 恢复策略

恢复必须有上限，不允许无限重试：

```text
首次错误 → 清状态/重启传输
连续错误 → 重置设备或总线
超过阈值 → 降级、隔离设备、告警或系统复位
```

重试间隔应考虑退避，并保留最后错误、累计次数和恢复次数。
