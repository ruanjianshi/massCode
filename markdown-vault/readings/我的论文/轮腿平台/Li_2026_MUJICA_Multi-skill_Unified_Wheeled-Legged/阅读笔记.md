## 🎯 研究目标

让**一个纯本体感知（blind）策略网络**同时掌握三类动力学差异极大的技能，并能自主切换、真机零样本部署：

1. **全向移动**（omnidirectional moving，含楼梯/坡/离散/粗糙地形）
2. **高台攀爬**（high platform climbing，最高 1 m）
3. **跌倒恢复**（fall recovery，任意姿态翻身）

作者指出现有方法的三个痛点：
- **技能太同质** — 大多 blind 多技能控制器只能做「平地/斜坡走」「爬楼梯」这类动作空间相近的低难度技能。
- **切换靠人手** — 动力学差异大的技能（galloping/ambling/crawling）通常靠人工切换，且只为展示多技能范式，不为适应复杂地形。
- **电机约束太糙** — RL 里的物理限制多被简化成动作惩罚或最大力矩上限，**忽略了 DC 电机「高速时最大力矩下降」的速度依赖特性**，既不安全也没榨出电机性能。

## 💡 核心贡献

1. **统一控制架构** — 单个 blind 策略联合训练全向移动 + 高台攀爬 + 跌倒恢复，用**技能指示器 ζ_t** 区分。
2. **安全感知学习 + DC 电机硬约束** — 显式建模「电机转速 ↔ 最大力矩」关系（小腿关节还额外依赖关节位置，呈余弦关系），数据取自宇树官方电机手册。
3. **高层技能选择器** — 仅凭本体感知历史自动选 ζ，用统一的速度跟踪奖励训练，实现无外感知的无缝切换。
4. **真机验证** — Go2-W 上零样本 sim-to-real：30° 楼梯上倒扣姿态恢复、20 cm 楼梯连续攀爬、**户外 80 cm / 室内 1 m 高台攀爬**（作者称此前无轮腿工作做到过）。

## 🔧 方法

### 问题表述：C-POMDP（约束部分可观 MDP）

```
max E_π[ Σ γ^t R(s_t,a_t,s_{t+1}) ]
s.t. E_π[ Σ γ^t C_i(s_t,a_t,s_{t+1}) ] ≤ δ_i ,  i = 1..k
```

### 观测与状态

| 类别 | 内容 |
|:---|:---|
| **观测 o_t（actor，部署可得）** | 机身角速度 ω_b(3)、投影重力 g_b(3)、指令 cmd(3)、关节位置 q(16)、关节速度 q̇(16)、上一步动作 a(16)、**技能类型 ζ(1)** |
| **特权观测 s_t（critic，仅仿真）** | o_t + 机身线速度 v(3) + 碰撞状态 c(18) + **轮地距离 u(4)** + 局部高程图 h(187) |

### 动作与 PD

- 腿关节动作 = 相对默认姿态的角度偏移；**轮关节动作 = 期望电机转速**。
- 轮子只走 D 项，腿关节走完整 PD：
  ```
  τ_i = K_d^i (q̇_i − a_i)                 若 i 为轮
  τ_i = K_p^i (q_i − a_i) − K_d^i q̇_i     其他关节
  ```

### 状态估计器（受 HIM 启发）

- GRU 在线编码器吃过去 **H = 6 帧**观测，输出 f_t = [v̂, ĉ, û, ê]：
  - **v̂** 机身线速度 → 判别稳定/不稳定运动区
  - **ĉ** 各部件碰撞概率 → 用「头部碰撞」感知前方台沿以准备攀爬，也支撑地形自适应恢复
  - **û** 轮地距离 → 反映地形起伏，平地上抑制无谓抬腿，协调轮腿
  - **ê** 隐状态向量
- 监督：参考编码器把 o_{t+1} 映到 e_t 作为目标 + **SwAV 对比学习损失**
  ```
  L_Estimate = L_Pred + L_SwAV(e_t, ê_t)
  L_Pred = MSE(v, v̂) + BCE(c, ĉ) + MSE(u, û)
  ```

### 非对称 Actor-Critic + P3O 约束优化

- actor 输入 = 历史嵌入 f_t + 当前观测 o_t；**两个 critic**（reward critic + constraint critic）都吃特权观测。
- 用 **P3O**（Penalized PPO）把约束问题转成惩罚式无约束目标：
  ```
  L_P3O = L_R^CLIP + κ Σ_i max{0, L_Ci^CLIP}
  ```

### 多任务奖励与约束（Table I）

| 项 | 公式要点 | 适用技能 |
|:---|:---|:---|
| R_cmdv | exp(−‖cmd_xy − v_xy‖²/σ²) | i, ii |
| R_cmdω | exp(−‖cmd_ω − ω_z‖²/σ²) | i |
| R_gravity | exp(−∠(g_b, g_world)/σ²) | iii |
| R_poserr | exp(−‖q − q_stand‖²/σ²)，仅当姿态角误差 < ε 时生效 | iii |
| **C_DC-motor** | Σ 1[\|τ_i\| ≥ τ_limit^i] | i, ii, iii |
| C_collision | 大腿/小腿接触计数 | i, ii |

- **碰撞约束只加在大腿和小腿** → 逼机器人**用轮子而不是腿去接触环境**。
- **DC 电机约束**（本文最实用的一条）：低速时最大力矩恒定，高速时随转速**线性下降**；小腿关节的最大力矩还随关节位置呈**余弦依赖**（因为它连接大腿与小腿连杆）。参数来自宇树官方电机手册，模型思路来自 Shin 2023 actuator-constrained RL。

### 两阶段训练

- **Training S1**：显式给定正确 ζ，训练底层多技能策略（30,000 iters）。
- **Training S2**：冻结底层策略，训练高层技能选择器（10,000 iters）——输入过去 H 帧观测（**去掉 ζ**），输出技能概率分布，用统一速度跟踪奖励训练，同样非对称 actor-critic。
- 频率：底层与高层都 **50 Hz**，物理仿真 200 Hz。
- **回合设置**：跌倒恢复每回合 6 s = 随机姿态空中自由落体 2 s + 恢复 4 s，**期间不终止**；其他任务 20 s，机身碰撞即终止。

### 课程学习（33 × 20 网格多任务环境）

4096 个机器人按行分配地形/任务，列为难度等级 l ∈ [1,20]：

| 地形 | 参数 |
|:---|:---|
| 楼梯 | 踏面 0.3 m，踏高 0.05 + 0.18·l/20 m |
| 斜坡 | 坡度 0.5·l/20 × 100% |
| 离散地形 | 30 个矩形凸起，宽 1~2 m，高 0.05 + 0.17·l/20 m |
| 粗糙地形 | 高度 U[0.04, 0.12] m |
| 坑（高台攀爬用） | 2 m × 4 m，深 0.05 + l/20 m —— **把「爬高台」建模成「从坑里爬出来」，可任意方向攀爬** |

- 晋级/降级规则：移动与攀爬看速度跟踪保持时长 / 实际行进距离是否远低于理论值；跌倒恢复看是否进入标准站姿邻域。

### 域随机化（Table II）

静摩擦 U[0.6,1.0]、动摩擦 U[0.4,0.8]、机身质量偏置 [−1.0, 3.0] kg、每 2~3 s 施加 [−10,10] N 外力、每 8~12 s 在 x/y 方向推 [−1,1] m/s、电机增益乘子 [0.8,1.2]。

## 🧪 实验

### 基线与消融（5 个代表任务 × 10 个难度级，难度间隔为训练时的 2 倍，4 个随机种子）

对比对象：MUJICA / w/o Velocity / w/o Wheel Height / w/o Collision / DreamWaQ + P3O / Vanilla PPO

- MUJICA 全面胜出，**难度越高差距越大**。
- 三个估计目标缺一不可；**去掉速度估计对非恢复任务尤其致命**。
- 优于 DreamWaQ+P3O → 说明估计目标的选择（速度 + 轮地距离 + 碰撞）比通用 VAE 隐变量更契合轮腿任务。
- **Vanilla PPO 完全学不会跌倒恢复**（缺状态估计），但因轮腿机动性太强，连 PPO 都能过斜坡；斜坡恢复所有方法都能做，因为光滑坡面上可借外力滚。

### DC 电机约束消融（最有说服力的一段）

| 条件 | 结果 |
|:---|:---|
| 无约束 | 大腿关节力矩-速度分布 **>90% 样本落在电机可行域外**（图截断到 ±100 N·m，实际更多超标离群点）；关节持续震荡；高台攀爬时后大腿关节频繁顶到正向关节限位，在限位处蹬地产生巨大力矩 → **真机直接触发电机故障** |
| 有约束 | 分布基本落在可行域内，**违规率降到 3.5% 以下**，关节行为稳定可执行 |

### 技能选择器评估（连续三任务串联，难度 5/10，100 回合）

| 方法 | 楼梯恢复 | 楼梯攀爬 | 高台攀爬 |
|:---|:---:|:---:|:---:|
| w/o indicator（共享奖励） | ✗ 训练崩溃 | ✗ | ✗ |
| w/o indicator（分任务奖励） | 72% | 72% | 38% |
| **with skill selector（本文）** | **95%** | **95%** | **91%** |

结论：**只靠奖励工程无法整合多技能**；没有显式指示器，策略无法解耦任务特定策略（比如「左转 vs 右转」这类冲突动作）。

### 真机实验（Go2-W，零样本）

- **楼梯恢复**：30° 楼梯上从倒扣状态恢复，**用小腿击地产生力矩翻转机身**。
- **楼梯攀爬**：不同踏高、边缘不规则的楼梯稳定上行；20 cm 楼梯。
- **高台攀爬**：户外 80 cm，室内 **1 m**（接近机械与驱动极限）。动作序列 = **后腿大腿关节下蹲蓄能 → 前腿伸出勾住箱沿 → 后腿协调上提**，完整轮腿协同。
- **多技能连续任务**：从随机摔倒姿态起 → 恢复 → 爬楼梯 → 过坡 → 爬 60 cm 高台，全程选择器凭本体感知自动切换，无人干预。
- 全程**电机保护机制（过流/过热）未触发**。

## 🚀 可直接移植到 UniLab 的清单

1. **技能指示器 ζ 加进观测**（最高优先）
   在 obs 里加一维（或 one-hot）技能 ID，把你现有 walk / jump / toe_walk / stairs 的奖励项按 ζ 做掩码，用一个策略联合训练。注意：**共享奖励会直接训崩**，必须分技能奖励 + 显式 ζ。
2. **DC 电机速度依赖力矩约束**（安全刚需）
   查你电机手册，实现 `τ_limit(q̇)`：低速恒定、高速线性下降；膝/小腿关节再加位置余弦项。作为 P3O constraint（`C = Σ 1[|τ| ≥ τ_limit]`）而不是软惩罚。这是后空翻上真机前必须补的一环。
3. **状态估计器三件套**：GRU 吃 6 帧历史，预测机身线速度（MSE）+ 各部件碰撞概率（BCE）+ **轮地距离**（MSE）+ SwAV 对比隐变量。轮地距离对你两轮足的「平地别乱抬腿」特别有用。
4. **碰撞约束只打大腿/小腿** → 强制用轮子接触环境，避免腿部磕碰。
5. **「爬高台」建模成「从坑里爬出」**：省去造台阶的方向性问题，任意方向可攀爬，课程只需调坑深。
6. **高层选择器（Training S2）**：冻结底层策略，仅用统一速度跟踪奖励训练一个 50 Hz 的技能分类器，输入去掉 ζ 的历史观测。你以后加 backflip 技能时只需重训选择器。
7. **P3O 而非纯 PPO**：双 critic（reward + constraint），把关节限位、力矩、碰撞都做成约束而非奖励项，减少奖励调参。

## 🎯 对后空翻计划的直接启示

1. **后空翻必须挂 DC 电机约束**。无约束时本文观察到「>90% 样本超出电机可行域 + 关节顶限位处蹬地 → 真机电机故障」，后空翻的起跳瞬间正是同一工况，不加约束仿真里能翻、真机上必炸。
2. **蓄能动作模板已有现成参考**：1 m 高台攀爬的「后腿下蹲蓄能 → 前腿伸展勾挂 → 后腿协调上提」，把「勾挂」换成「腾空翻转」，就是后空翻的动作骨架。
3. **落地即恢复**：把 backflip 与 fall recovery 放进同一策略、共享 ζ，失败落地立刻由选择器切到恢复技能——这才是真机上敢反复试空翻的前提。
4. **技能选择器让空翻可被「触发」**：未来可让选择器基于本体感知自主决定何时空翻（如检测到需要越障），而不是靠人按键。

## ❓ 待解答的问题

1. ζ 的具体编码方式？标量还是 one-hot？三技能之外扩展到 6~8 技能时是否需要嵌入层？
2. P3O 的惩罚因子 κ 和各约束阈值 δ_i 怎么取？论文未给数值（需看项目页或代码）。
3. 是否会开源？IsaacLab 实现 + Go2-W 配置若开源，你的移植成本会大幅下降。
4. 高层选择器只用「统一速度跟踪奖励」，那跌倒恢复（不跟踪速度）的切换信号从哪来？推测靠「躺着无法跟踪速度 → 恢复技能能提升速度奖励」间接学到，需要验证。
5. 两轮足（你的构型）没有四轮的静态稳定性，跌倒恢复时「小腿击地翻身」这招是否可行？两轮更依赖轮子反向转动缓冲（Deng 2025 的做法）。
6. 1 m 高台攀爬的成功率是多少？论文只给了定性演示，未给统计。

## 💭 思考与延伸

这篇是**架构层面**的论文，和你已读的两篇正好形成三层递进：

```
Hou_2026 FTSR        →  单技能怎么做好（两阶段 + 力引导）
Deng_2025 DS         →  单技能怎么训出来（动态奖励整形解探索-收敛困境）
Li_2026 MUJICA       →  多技能怎么整合（ζ 指示器 + 选择器 + 电机硬约束）
                            ↓
        你的 xqrobotwl 统一策略：walk / toe / stairs / jump / recovery / backflip
```

**最有价值的两句话**：
- 「只靠奖励工程无法整合多技能」——共享奖励会训崩，分任务奖励在中等难度上也只有 38~72%，**必须有显式技能指示器**。
- 「忽略 DC 电机的速度依赖力矩限制，既牺牲安全也浪费性能」——加上硬约束后违规率从 >90% 降到 <3.5%，且**电机保护机制全程未触发**，反而榨出了更多性能。
