## 🎯 研究目标

解决轮腿机器人跌倒恢复中的两个核心矛盾：

1. **稀疏奖励下的探索-收敛困境** — 只用「最终目标姿态」当奖励，反馈太稀疏；若过早重罚姿态偏差，策略会被压成保守动作、陷入局部最优（只用后腿撑，前腿不敢动）。
2. **轮子的作用没人量化** — 已有跌倒恢复几乎都是「纯腿」方案（含 Castano 2019 同组的稳定性特征空间法），轮腿协同恢复的潜力未被挖掘。

## 💡 核心贡献

1. **Episode-based Dynamic Reward Shaping（DS，按回合动态奖励整形）** — 奖励权重随回合内时间步递增，早期放开探索、后期收紧姿态精度，配合课程学习。
2. **首次定量验证轮子驱动的价值** — 跨平台实验证明主动轮降低关节力矩 15.85%（KYON）/ 26.24%（Go2-W），并显著降低站起后稳定阶段的高度方差。
3. **跨平台零调参泛化** — 同一套超参在 KYON 与 Go2-W 上分别达 99.1% / 97.8% 成功率，无需平台特定调参；在 5 类未见崎岖地形上有部分 zero-shot 能力。

## 🔧 方法

### 状态初始化（造摔倒姿态）

- 随机化机身姿态 + 关节角，**关节力矩置零**，从 **1.1 m 自由落体 2 s**，确保完全摔透（避免动力学不真实，沿用 Hwangbo 2019 的做法）。
- 每回合固定 **4 s，绝不提前终止**（no early termination）——这点很关键，逼策略必须把动作做完。

### 非对称 Actor-Critic（Asymmetric PPO）

| 网络 | 观测 |
|:---|:---|
| **Actor（100 Hz）** | 机身线速度/角速度/姿态、关节位置/速度、轮速 + 历史（间隔 0.01 s）+ 上一步动作；除最新动作与关节位置外全部注入**高斯噪声**（关节速度与机身线/角速度噪声更大） |
| **Critic** | 加特权信息：**碰撞状态** + **VTG（Vector-To-Goal）**，仅仿真可得，用于加速收敛 |

### 动作空间

- 关节位置目标 = `s_p · a_p + q`，轮速目标 = `s_v · a_v + q_v`
- **经验教训：`s_v > 1.0` 时轮子明显震荡**，故取 `s_v < 1.0` 降低指令敏感度。
- 关节走位置 PD，轮子走速度控制器。

### DS 动态奖励整形（核心公式）

```
DS = (a · t / T)^k          t ∈ [0, T]，k 为增长率，a 为基线系数
```

总奖励：

```
r_t = DS · r_jointpos + r_baseheight + r_baseori
    + CW · r_collision
    + DS · (r_actionrate + r_jointvel + r_torque + r_jointacc)
    + r_wheelvel
```

要点：
- **关节位置项与全部平滑性惩罚项都乘 DS** → 回合早期几乎不罚，机器人敢做大幅翻滚/甩腿；后期权重升高，收敛到干净的目标姿态。
- **base height / base orientation 不乘 DS** → 目标始终在线，保证任务方向不丢。
- **action rate 计算时排除轮子动作** → 让轮子自由高频使用。
- 额外**支撑状态奖励**：四轮同时触地时给奖，用于站起后稳住。

### 域随机化与训练配置

- 机身质量 ±5 kg，连杆质量 ±10%，静摩擦 U[0.7, 1.3]，驱动器刚度 ±15.0 / 阻尼 ±2.0，动作噪声 σ=0.02。
- 控制频率 100 Hz，仿真 1000 Hz；PPO lr = 0.001，γ = 0.99。
- **课程学习**：难度因子从 0.3 起，按 0.968 指数衰减，逐步放开探索。

## 🧪 实验

### 成功率（2048 个随机初始状态）

| 平台 | 策略 | 成功率 |
|:---|:---|:---:|
| KYON | **DS** | **99.1%** |
| KYON | Baseline | 96.4% |
| Go2-W | **DS** | **97.8%** |
| Go2-W | Baseline | 94.1% |

成功判据：末步机身高度 > 0.42 m、关节角偏离默认 ≤ 0.5 rad、最大关节速度 < 0.1 rad/s。

### 为什么 baseline 会失败

- 失败集中在「前腿关节角随机幅度很小」的初始状态：因为存在关节角偏差惩罚，baseline **压制前腿运动**，只想用后腿抬机身 → 局部最优卡死。
- PCA 分析动作序列方差：DS（σ²PC1=20.91, σ²PC2=9.72）> Baseline（17.33, 5.22），证明 DS 确实扩大了动作空间探索边界。

### 轮子的贡献（wheel-active vs wheel-fixed）

| 平台 | 主动轮 | 固定轮 | 降幅 |
|:---|:---:|:---:|:---:|
| KYON（max 132 N·m） | 35.776 N·m | 42.515 N·m | **15.85%** |
| Go2-W（max 23.7 N·m） | 7.123 N·m | 9.657 N·m | **26.24%** |

- 两者机身高度都能在 **0.7 s** 内收敛到 0.42 m，但纯腿模式在稳定阶段（0.7~1.5 s）抖得厉害（t=1 s 方差 0.102）。
- 机理解释（两条）：① 轮子滚动把动能转成关节位能，减少关节抗重力功；② 主动轮允许**足端接触滑移**，降低内力——固定轮时接触点不能滑，内力更大、额外压关节。
- Go2-W 的典型恢复过程（Fig.11）：站起后机身后倾 → **轮子反向转动缓冲**防翻倒 → 质心稳定后正向转动快速调机身高度与关节构型。

### 未见地形（zero-shot）

5 类程序化地形：Random Boxes（0.05~0.2 m）、Rough（δ=0.02~0.10 m）、Sloped Pyramid（20~60% 坡）、Pyramid Stairs（0.05~0.23 m）、Inverted Pyramid Stairs。

| 平台（非平坦地形） | DS | Baseline |
|:---|:---:|:---:|
| KYON | **78.6%** | 61.8% |

- 有部分零样本泛化，但**明显下降，楼梯上频繁二次摔倒**。作者归因：策略无地形感知；无法按局部地形调整恢复姿态。

## 🚀 可直接移植到 UniLab 的清单

1. **DS 因子（最高优先，改动最小）**
   在 reward manager 里加 `ds = (a * step / max_steps) ** k`，乘到 `joint_pos`、`action_rate`、`joint_vel`、`torque`、`joint_acc` 这几项上；`base_height`、`base_ori` 保持常权重。
2. **回合不提前终止**：跌倒恢复/后空翻训练把 early termination 关掉，固定 4 s（后空翻可 2~3 s），只靠奖励塑形而不是靠 reset 惩罚。
3. **摔倒状态生成器**：随机姿态 + 零力矩 + 1.1 m 自由落体 2 s，比手工摆姿态更真实、覆盖更广。
4. **非对称 critic**：critic 加 collision state + VTG（到目标姿态向量），actor 不给；配合观测注噪（关节速度/机身速度噪声更大）。
5. **轮速缩放 `s_v < 1.0`**：你的轮子若用速度指令，直接避坑轮子震荡。
6. **action rate 排除轮子**：允许轮子高频动作，这是「轮子当反作用飞轮」的前提。
7. **四轮/双轮触地支撑奖励**：站稳阶段的稳定项，你两轮版本改成「双轮同时触地 + 俯仰角收敛」。

## 🎯 对后空翻计划的直接启示

后空翻 = 蓄力 → 起跳 → 空中翻转 → 落地，正好也是「早期需要疯狂探索、后期需要精确姿态」的结构，DS 可以按阶段用：

```
t/T ∈ [0, 0.3]   蓄力+起跳：DS≈0，几乎不罚姿态/平滑，鼓励大力甩腿蓄角动量
t/T ∈ [0.3, 0.7] 空中翻转：翻转角进度奖励为主（不乘 DS），平滑惩罚仍轻
t/T ∈ [0.7, 1.0] 落地稳定：DS→1，姿态/力矩/加速度惩罚全上，逼出干净落地
```

**轮子在空中就是飞轮**：本文证明轮子转动能转移动量、缓冲姿态。后空翻空中阶段可用轮子角动量微调翻转速度（相当于 Xiong_2020 flywheel SLIP 里的飞轮，但你不需要额外硬件）。

## ❓ 待解答的问题

1. DS 公式里的 `a` 和 `k` 具体取值？论文正文写「For our experiments…」但表格里没给全，需要看项目主页或复现调参（建议先试 `k=2, a=1`）。
2. **全是仿真，没有真机实验** — sim-to-real 差距未验证（作者把它列为 future work），这是本文最大短板。
3. DS 乘在平滑惩罚上会不会让早期动作过于暴力伤硬件？论文用 collision penalty（常权重 CW）兜底，真机上是否够？
4. 楼梯上二次摔倒怎么解？加高度扫描/深度感知后 DS 还需不需要改？
5. 回合固定 4 s 对后空翻是否太长？空翻需要更短窗口 + 更高时间分辨率。
