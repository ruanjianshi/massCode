# Huang 2025｜MoE-Loco：多任务运动的专家混合

## 📋 基本信息

- **作者:** Runhan Huang*、Shaoting Zhu*（共同一作）、Yilun Du、Hang Zhao†
- **单位:** 清华大学交叉信息研究院（IIIS）、上海期智研究院（Shanghai Qi Zhi Institute）、MIT
- **通讯:** Hang Zhao（赵行）
- **平台:** **Unitree Go2**（标准四足，非轮腿），板载 NVIDIA Jetson Orin
- **仿真:** Isaac Gym，4096 并行，单张 RTX 3090
- **控制频率:** 仿真与真机均 **50 Hz**；PD 增益 $K_p=40.0$、$K_d=0.5$
- **专家数:** $N_{exp} = 6$
- **版本:** arXiv:2503.08564v2（2025-05-21），9 页
- **项目页:** https://MoE-Loco.github.io/

## 🎯 研究目标

用**单一策略**同时掌握 **9 个** 运动任务，跨越**两种步态模式**（四足 + 双足）与多种地形，并解决多任务 RL 中的**梯度冲突**。同时探索 MoE 带来的额外好处：**技能自动分解、可解释性、以及技能重组（skill composition）**。

## 💡 核心贡献

1. 把 MoE 同时引入 **Actor 和 Critic**，共享同一个门控网络，缓解梯度冲突
2. **量化证明**梯度冲突被缓解（余弦相似度 + 负梯度分量比例两个指标）
3. 发现专家**自发涌现出人类可理解的技能**（平衡专家、抬前腿跨越专家），并可通过**手动调门控权重零样本合成新步态**
4. 真机零样本部署，9 个任务全部验证

## 🔧 方法

### 1. 任务定义（9 个任务）

| 步态 | 任务 |
|:---|:---|
| **四足（q）** | 跨横杆（bar crossing）、跨坑（pit crossing）、**钻挡板（baffle crawling）**、爬楼梯、走斜坡 |
| **双足（b）** | **站起（standing up）**、平地行走、走斜坡、下楼梯 |

**多任务 MDP 的形式化**（这段论述很有用，可引用）：$\langle S_\tau, A_\tau, T_\tau, R_\tau, \gamma_\tau\rangle$

- 不同地形对应**状态空间的不同子集** $S_\tau \subseteq S$，且完整状态空间 $S$ 对机器人**不可知**
- **奖励函数 $R$ 随步态而变**（四足与双足奖励不同）
- **终止条件随步态而变** → 导致**转移动力学 $T$ 也不同**

$$J(\pi) = \mathbb{E}\Big[\sum_\tau \sum_{t=0}^{\infty}\gamma^t R_\tau(s_t,a_t,s_{t+1})\Big]$$

> 🔑 **注意这一点极其重要**：作者明确承认**不同任务的奖励函数与转移动力学都不同**（$R_\tau$、$T_\tau$），却仍然用一个联合反传的 MoE 去优化它们的**加和**。这是软门控路线的一个理论松弛处 —— 它把「多个不同的 MDP」硬拼成「一个平均 MDP」。**你可以在这里做文章**：当技能间的 $R_\tau$ 与 $T_\tau$ 差异进一步扩大（如后空翻需要外力辅助课程、需要 N3PO 约束集），这个加和目标就不再是一个合理的优化对象。

### 2. 状态空间（四类观测）

| 观测 | 内容 |
|:---|:---|
| **本体感知 $p_t$** | IMU 的重力投影 + 基座角速度、关节位置、关节速度、上一步动作 |
| **显式特权 $e_t$** | **基座线速度**（作者注：IMU 数据噪声太大不可用）+ **地面摩擦系数** |
| **隐式特权 $i_t$** | **各连杆接触力** —— 必须编码成低维隐变量以缓解 sim-to-real gap |
| **指令 $c_t$** | 速度指令 $V=(v_x,v_y,v_{yaw})$ + **one-hot 步态向量 $g$**（$g=0$ 四足，$g=1$ 双足） |

**动作空间**：$a_t\in\mathbb{R}^{12}$，12 个关节的目标位置。

> 💡 **one-hot 步态向量 $g$ 就是 MUJICA 的技能指示器 ζ 的简化版**。三篇（MUJICA 的 ζ、Chamorro 的地形布尔量、本文的 one-hot $g$）指向同一个结论：**多技能单策略必须有显式的模式条件输入**。你的调度器输出本质上就是这个 $g$，只是你的 $g$ 用于选择独立专家而非条件化单网络。

### 3. 网络架构

```
i_t ──Enc──┐
e_t ───────┼── l_t = [Enc(i_t), e_t, p_t] ──LSTM──► h_t ──┬──► Gating Network ──► ĝ
p_t ───────┘                                              ├──► Actor MoE  {f_i}  ──► Σ ĝ_i·f_i(h_t) = a_t
                                                          └──► Critic MoE {l_i}
```

**MoE 模块（软门控，注意与 He 2026 的 Top-1 硬选择不同）**：

$$\hat g_i = \mathrm{softmax}(g(h_t))[i], \qquad a_t = \sum_{i=1}^{N} \hat g_i \cdot f_i(h_t)$$

**三个关键架构决策**：
1. **Actor 与 Critic 都用 MoE** —— critic 用 MoE 是为了「更好地捕捉多样的任务奖励结构」
2. **Actor MoE 与 Critic MoE 共享同一个门控网络** —— 保证策略评估与动作生成的一致性
3. **门控输入是 LSTM 的输出 $h_t$**，而非原始观测（对比 He 2026 门控直接吃 $S_t$）—— 意味着门控可以利用**时序信息**做路由

**网络尺寸（Table VI）**：

| 模块 | 类型 | 维度 |
|:---|:---|:---|
| Actor RNN / Critic RNN | LSTM | [256] |
| Estimator Module | LSTM | [256] |
| Estimator Latent Encoder | MLP | [256, 128] |
| Implicit Encoder | MLP | [32, 16] |
| **Expert Head ×6** | MLP | [256, 128, 128] |
| **Standard Head（参数量对齐基线）** | MLP | **[640, 640, 128]** |
| Gating Network | MLP | [128] |

> **同样做了参数量对齐**：`Ours w/o MoE` 用 [640,640,128] 的单头替换 6 个 [256,128,128] 专家头，总参数量相同。**两篇 MoE 论文（本文 + He 2026）都做了这件事，说明这是该领域的标配实验。你的第 8 章绕不过去。**

### 4. 奖励设计（按步态分支）

- 四足（$g=0$）：$r^{quad} = r^{quad}_{track} + r^{quad}_{reg}$
- 双足（$g=1$）：$r^{bip} = r^{bip}_{track} + r^{bip}_{stand} + r^{bip}_{reg}$

**Table V 中的关键奖励项**（挑对你有用的）：

| 类别 | 项 | 权重 | 说明 |
|:---|:---|---:|:---|
| 四足跟踪 | Tracking lin vel | **7.0** | $\exp(-\lVert v_{c,xy}-v_{b,xy}\rVert^2/\sigma)$ |
| 四足跟踪 | Tracking ang vel | 2.5 | — |
| 四足跟踪 | Ang vel stability | −1.0 | $(\omega_{t,x}+\omega_{t,y})^2$ |
| 四足跟踪 | **Feet in air** | **1.0** | 足端无接触 + 小腿有接触的组合指示 |
| 四足正则 | Joint pos / vel / acc | −0.05 / −0.002 / −2e−6 | — |
| 四足正则 | **Balance** | −0.1 | $\lVert F_{feet,0}+F_{feet,2}-F_{feet,1}-F_{feet,3}\rVert^2$（对角腿受力平衡） |
| 四足正则 | **Torque exceed limit** | −0.01 | $\sum_i\sum_j \max(\lvert\tau_{ij}\rvert-\tau_j^{limit}, 0)$，**按子步累加** |
| 双足站立 | **Orientation** | **−2.0** | $0.5\cos\theta+0.5$，$\theta=\arccos\frac{g\cdot t}{\lVert g\rVert\lVert t\rVert}$ |
| 双足站立 | Base height linear | 0.8 | $\mathrm{clip}\big(\frac{z_{root}-T_{min}}{T_{max}-T_{min}},0,1\big)$ |
| 双足站立 | 姿态门控高度奖励 | **3.0 / 2.5** | $\mathbb{1}(\cos\theta>0.95)\cdot\frac{z_{base}-s_{low}}{s_{high}-s_{low}}$ |
| 双足 | Termination / Alive | −1 / +1 | — |
| 双足正则 | Rear pos balance | — | $\lVert q_i^{rear\,left}-q_i^{rear\,right}\rVert^2$（左右后腿对称） |
| 双足正则 | 前腿相关项 | — | 均带 $\mathbb{1}(t>T_{allow})$ 时间门控 |

**两个值得偷的设计**：
1. **$\mathbb{1}(\cos\theta>0.95)$ 门控的高度奖励** —— 只有姿态正了才给「站高」的奖励。这与 EFGCL 的 $\rho^{task}\cdot\rho^{stand}$ 乘积门控是同一思想：**用逻辑门控代替权重调参**，防止退化解（比如躺着往上顶）
2. **$\mathbb{1}(t>T_{allow})$ 时间门控** —— 双足的前腿正则项在回合早期不生效，给「站起来」这个过渡阶段留出自由度。**这个技巧对你的后空翻起跳阶段直接可用**（起跳前 0.3 s 不惩罚关节速度/加速度）
3. **Torque exceed limit 按子步累加** —— 比只在控制步检查更严格，能抓住子步内的力矩尖峰

### 5. 终止条件（随步态而变）

- $g=0$（四足）：$\theta^{roll}>1.0$ 或 $\theta^{pitch}>1.6$ 即终止
- $g=1$（双足）：**1 秒后**，除后足与小腿外任何连杆触地即终止

### 6. 训练流程（PAS 两阶段，非标准教师-学生）

采用 **Probability Annealing Selection (PAS)** 范式 [54]（即作者同组的 SARO 工作）：

**阶段 1（Oracle 策略）**：全部观测 $[p_t, e_t, i_t, c_t]$ 可见。$i_t$ 经 encoder 编码 → 与 $e_t, p_t$ 拼成 $l_t$ → LSTM 整合历史得 $h_t$ → MoE 出动作。同时用 L2 损失 $L_{recon}$ **预训练 estimator**，让 $\mathrm{Estimator}(p_t,c_t)$ 重建 $[\mathrm{Enc}(i_t), e_t]$。

$$L = L_{surro} + L_{value} + L_{recon}$$

**阶段 2（纯本体感知）**：只能访问 $[p_t, c_t]$。estimator、LSTM、MoE 的权重从阶段 1 复制，然后用 PAS **按概率退火**逐步把输入从真实特权切换到估计值：

$$P_t \leftarrow \alpha^t, \qquad \bar l_t \leftarrow \mathrm{ProbabilitySelection}(P_t, \hat l_t, l_t)$$

其中 $\hat l_t = [\mathrm{Estimator}(p_t,c_t), p_t]$（估计），$l_t = [z_t, e_t, p_t]$（真实）。

> 💡 **PAS 比标准教师-学生蒸馏更值得你关注**。标准蒸馏是「训完教师 → 监督学生」，学生只学动作匹配，**会丢掉教师的探索能力**（Chamorro 的教训：教师-学生学不出迈步反射）。PAS 是**在 RL 过程中**按概率把真实特权替换为估计值，策略持续用 RL 更新 → 能主动适应估计误差。**对你的后空翻很关键**：根 pitch 角这类特权观测在真机上噪声大，用 PAS 比蒸馏更稳。

**训练量（Section IV-A，可作为你估算算力的参考）**：
- 平地行走（双步态）预训练：**40,000 iterations**
- 复杂地形任务：**80,000 iterations**
- PAS 适应纯本体感知：**10,000 iterations**
- 合计 **130,000 iterations**（单张 3090）

### 7. 技能组合（Skill Composition）—— 本文最有想象力的部分

利用预训练专家，**手动改门控权重**来合成新技能：

$$\hat g_i = w[i]\cdot \mathrm{softmax}(g(h_t))[i]$$

$w[i]$ 可手工指定或由另一个网络动态调整。这允许**可控的技能混合**，无需额外训练。

- RMA 几乎全线崩溃（0.000），说明纯 MLP + CNN encoder 的教师-学生路线无法处理这种任务跨度

### 2. 真机零样本部署（Fig. 4、Fig. 5）

**混合地形真机序列**（这是很硬的实测）：四足依次跨越 **20 cm 横杆 → 22 cm 挡板 → 15 cm 楼梯 → 20 cm 坑 → 30° 斜坡**，然后收到双足指令 → 站起 → 上 30° 斜坡 → 转身 → 下坡。

每个测试 **20 次试验**取平均成功率。另在户外多种环境测试（Fig. 5，9 个场景）。

### 3. 梯度冲突的量化（Table III / IV）—— **本文对你最有用的部分**

**实验设定**：从预训练 15000 epochs 的 checkpoint 恢复，跑 500 epochs 多任务训练（4096 个机器人），对梯度取平均。

**两个度量**：
1. **梯度余弦相似度**（↑ 越大冲突越小）：不同任务的全部参数梯度的归一化点积
2. **负梯度分量比例**（↓ 越小冲突越小）：每对任务梯度中，符号相反的分量所占百分比

**Table III：梯度余弦相似度（MoE / Standard）**

| | Baffle(q) | Stair(q) | Slope Up(b) | Slope Down(b) |
|:---|:---|:---|:---|:---|
| Bar(q) | 0.519 / 0.474 | 0.606 / 0.592 | **0.278 / −0.132** | **0.091 / −0.128** |
| Baffle(q) | — | 0.369 / 0.384 | **0.062 / −0.091** | **0.061 / −0.101** |
| Stair(q) | — | — | **0.046 / −0.023** | 0.052 / 0.015 |
| Slope Up(b) | — | — | — | 0.806 / 0.709 |

**Table IV：负梯度分量比例 %（MoE / Standard，↓ 更好）**

| | Baffle(q) | Stair(q) | Slope Up(b) | Slope Down(b) |
|:---|:---|:---|:---|:---|
| Bar(q) | 35.72 / 37.33 | 32.67 / 32.62 | **45.50 / 55.12** | 49.83 / 50.80 |
| Baffle(q) | — | 39.90 / 38.52 | **49.86 / 55.91** | 49.91 / 51.68 |
| Stair(q) | — | — | 49.52 / 50.15 | 50.04 / 50.34 |
| Slope Up(b) | — | — | — | **23.17 / 30.91** |

**必须看清的三点**：
1. **跨步态（q ↔ b）的标准策略余弦相似度是负数**（−0.132、−0.128、−0.091、−0.023）—— 这是**梯度冲突最直接的证据**：两个任务的梯度方向相反，一个变好另一个必然变坏。MoE 把它们全部拉回正值。
2. **但 MoE 拉回后的值也非常小**（0.046–0.278），且负梯度分量比例**仍在 45–50%**（几乎是随机的一半）。**换句话说：MoE 只是把冲突从「负相关」缓解到「几乎不相关」，并没有让任务变得协同。**
3. **同步态内任务（Bar/Baffle/Stair 之间）MoE 的改善很小，甚至有反例**（Baffle-Stair：0.369 / 0.384，MoE 反而更差；负分量比例 39.90 / 38.52，MoE 也更差）。

> 🔑 **这第 2、3 点是你辩护「完全解耦」的黄金论据。** 作者自己的数据表明：**软门控 MoE 对高度异构的任务只能把冲突降到「不相关」，做不到「无冲突」；而对相近任务甚至可能引入额外损失。** 那么当技能异构度进一步提高（后空翻 vs 滚动行走，比 双足 vs 四足 更远），残余的 45–50% 负梯度分量就会成为实质瓶颈。**完全参数解耦是把负梯度分量比例降到 0 的唯一方法。** 这句话可以直接写进你的第 3 章。

### 4. 训练性能（Fig. 6）

## 💭 思考与延伸

**1. 本文最大的贡献不是 MoE，而是那两张梯度冲突表。**

MoE 用在 locomotion 上并不新（Yang 等的 multi-expert learning 更早）。本文真正的学术价值在于**首次把「梯度冲突」这个一直被定性谈论的概念，在 legged locomotion 上做了严格的量化**，并给出了跨任务对的完整矩阵。而这两张表的数据**恰好不完全支持作者自己的结论** —— MoE 把余弦相似度从 −0.13 拉到 +0.28（跨步态最好的一对），听起来很好；但绝大多数任务对拉到的只是 0.05 左右，负梯度分量比例仍稳定在 45–50%。

**换句话说：软门控 MoE 的作用是「让任务之间互不干扰」，而不是「让任务之间互相帮助」。** 那么一个自然的追问是：如果目标只是「互不干扰」，**完全参数解耦不是更直接、更彻底吗？** 软门控付出了联合优化的复杂性、门控坍塌风险、增量时旧任务被扰动的风险，换来的是「几乎不相关」而非「无冲突」。**这个追问就是你整篇大论文的立论起点，而且它是从竞品自己的数据里长出来的 —— 这是最有力的论证方式。**

**2. 「参数共享」在多任务 locomotion 里可能是一个被高估的目标。**

NLP/CV 里参数共享有明确收益：任务共享底层特征（词法、边缘检测）。但 locomotion 的「底层特征」是什么？本文的 t-SNE 显示四足走坡与四足跨坑聚在一起（都是准静态行走），跨杆/钻挡板/爬楼梯彼此远离。也就是说，**共享只在动作分布相近的任务间发生，而这类任务本来用一个网络就能学**。真正困难的、跨度大的任务对，共享带来的是冲突而非增益。

这个观察可以推广成一个论点：**多任务 locomotion 中，参数共享的收益与技能相似度正相关，与技能异构度负相关。** 存在一个临界异构度，超过它之后共享是净损失。你的 7 个技能（含后空翻）大概率在临界点之外。**如果你能在第 8 章画出「技能异构度（用梯度余弦相似度度量）vs MoE 相对增益」的散点图，并显示出这个临界点，那是可以发期刊的贡献。**

**3. PAS 是本文被低估的部分，而它对你上真机可能比 MoE 更重要。**

标准教师-学生蒸馏的根本缺陷是：学生只学**动作匹配**，不再做 RL 探索，所以学不出教师那些依赖特权信息的反射性行为（Chamorro 的迈步反射就是这么丢的）。PAS 保持 RL 在环，只是逐步把特权输入换成估计值，策略能主动学会「在估计不准时怎么办」。

**对你后空翻的具体意义**：后空翻的特权观测是根 pitch 角与根高度。真机上 IMU 的 pitch 在翻转过程中会有严重的积分漂移与 $\pm\pi$ 跳变，估计误差不是小噪声而是**结构性偏差**。蒸馏出的学生会在这个偏差上直接失效；而 PAS 训出的策略在训练中就见过「估计值不准」的情况。**建议你的 backflip.py 从一开始就按 PAS 而非蒸馏来设计。**

**4. 一个我认为作者遗漏的关键实验：新增专家后的旧任务退化。**

Fig. 10 的三足步态实验设计得很漂亮（新专家 + 冻结旧专家 + 只训门控），但**只报告了新任务成功，完全没报告旧任务**。而门控网络被重训意味着**所有旧任务的路由都改变了**。旧专家参数没变，但它们被调用的权重组合变了 → 旧任务的实际输出动作变了 → 性能可能退化。

**这个空白就是你的机会。** 你的方案里旧专家**和**调度器的旧任务部分都可以冻结（只在调度器的输出层扩一维），能做到**严格零退化**。这是一个可以精确证明、审稿人无法反驳的性质。**我强烈建议把「增量扩展时的旧技能性能保持率」作为第 8 章的一个独立指标（你的方案 100%，MoE 基线待测）。**

**5. 对你「技能组合做不到」的一点补充想法。**

本文的运球步态合成确实是软门控独有的能力，你的方案做不到。但换个角度：**你的调度器可以做「时序上的技能组合」而非「空间上的混合」** —— 比如「跳跃专家 → 空中切换到后空翻专家」这种序贯组合，本文的软门控反而难做（因为门控是逐步的软混合，无法保证在关键时刻做干净的切换）。**建议在第 7 章明确提出「序贯技能组合」这个概念，作为对「混合式技能组合」的对偶**。这样你就不是「缺少一个能力」，而是「提供了另一种能力」。
